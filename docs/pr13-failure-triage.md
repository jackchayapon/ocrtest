# PR #13: failure-by-failure triage

ผล full rerun สุดท้าย: backend **545 passed / 0 failed / 0 skipped** และ Playwright **188 passed / 0 failed / 0 skipped**, exit0 ทั้งคู่ รายการ baseline89ด้านล่างได้รับการตรวจและมี coverage ในชุดปัจจุบัน ไม่มี test ถูกลบ/skip การเปลี่ยน obsolete assertions อ้างอิง source behavior เดิมและไม่ย้อน code ให้เหมือน fixtures คำตัดสิน Production ยังคง **NO-GO** ตาม memory/authorization/uploads gates

ขอบเขต baseline: independent backend ที่ 7b8caf2 (480 ผ่าน/55 ล้มเหลว) และ full browser artifact ก่อน remediation (137 ผ่าน/34 ล้มเหลว) ไม่อ้างว่า baseline เคยผ่าน ไม่มี test ถูกลบหรือ skip รายการนี้ระบุ failure เดิมทุก ID รวม parameterized cases แยกแถว

หลักฐาน source: `seed.py` ไม่สร้าง built-ins, `BenchmarkRepository.config/configs` กรอง execution_mode, `PipelineManager` ใช้ Dynamic adapter; lean logs/raw response และ synchronized GT เป็น behavior ก่อน remediation แล้ว Catalog fixture มีโมเดล/definitions จริง ไม่ monkeypatch manager ให้สร้างผลสำเร็จ

การแก้ fixture ไม่ใช่หลักฐานว่า production ไม่มีบั๊ก: พบแยกและแก้ Dynamic PUT /pipelines/{id} 500 และ terminal elapsed ที่นับต่อหลังจบ พร้อม regression ใหม่ Debug ปิด fail closed; API authorization gap ยังอยู่ Dataset refresh ตั้งใจล้าง selection ไม่แก้ production เพื่อรองรับ fixture เก่า

## Environment / ข้อจำกัดหลักฐาน

ระหว่าง remediation เคยเริ่ม PostgreSQL suite ขณะ local Docker/PG ไม่ทำงาน จึงมี connection timeout; ไม่นับเป็น product defect ผลสุดท้ายต้องอ้าง full rerun หลัง PG พร้อมเท่านั้น Resource harness เคยอ่าน 502 ระหว่าง controlled kill/start แล้วหยุด แก้ harness ให้รอ reconnect โดยยังตรวจผลครบและ unique IDs ไม่มีการปลอม API success

ไม่มี failure ที่จัดเป็น unconfirmed ถูกประกาศผ่านจากการเปลี่ยน fixture อย่างเดียว ผล full suites และความเสี่ยง memory/security/uploads ให้ดู [remediation report](pr13-remediation.md)
